# 快速修复 Safari 无法访问 API

## ✅ 后端服务已启动

后端服务现在正在运行，可以从 Mac 访问：
```bash
curl http://192.168.1.6:3000/health
# 返回: {"status":"ok","timestamp":"..."}
```

## 🔧 如果 iPhone Safari 仍然无法访问

### 方法 1: 检查防火墙（最常见原因）

1. **打开系统设置**
   - 系统设置 > 网络 > 防火墙

2. **配置防火墙**
   - 如果防火墙已启用：
     - 点击 **"选项"** (Options)
     - 取消勾选 **"阻止所有传入连接"**
     - 或者添加 Node.js 到允许列表
   - **或者临时关闭防火墙测试**

3. **重启后端服务**（如果修改了防火墙）
   ```bash
   # 停止当前服务
   lsof -ti:3000 | xargs kill -9
   
   # 重新启动
   cd wanderlog_api
   npm run dev
   ```

### 方法 2: 验证网络连接

1. **确认 Mac 和 iPhone 在同一 Wi-Fi**
   - Mac: 系统设置 > 网络 > Wi-Fi
   - iPhone: 设置 > Wi-Fi
   - 确保连接到同一个网络

2. **验证 Mac IP 地址**
   ```bash
   ipconfig getifaddr en0
   ```
   应该显示：`192.168.1.6`（或类似的 IP）

3. **在 iPhone Safari 中测试**
   - 打开 Safari
   - 输入：`http://192.168.1.6:3000/health`
   - 应该看到 JSON 响应

### 方法 3: 检查路由器设置

某些路由器可能阻止设备间通信：
- 检查路由器是否启用了"AP 隔离"或"客户端隔离"
- 如果启用，需要关闭此功能

## 🧪 测试步骤

### 1. 从 Mac 测试（应该成功）
```bash
curl http://192.168.1.6:3000/health
```

### 2. 从 iPhone Safari 测试

1. 打开 Safari
2. 在地址栏输入：`http://192.168.1.6:3000/health`
3. 按回车

**应该看到**：
```json
{"status":"ok","timestamp":"2026-01-22T20:37:38.538Z"}
```

**如果看到错误**：
- "无法连接到服务器" → 检查防火墙
- "Safari 无法打开页面" → 检查网络连接
- 页面一直加载 → 检查后端服务是否运行

## 📝 快速检查清单

- [ ] 后端服务正在运行（`lsof -i :3000`）
- [ ] 可以从 Mac 访问 `http://192.168.1.6:3000/health`
- [ ] Mac 和 iPhone 在同一 Wi-Fi 网络
- [ ] Mac 防火墙允许端口 3000（或已关闭）
- [ ] Mac IP 地址正确

## 🎯 如果仍然无法访问

1. **临时关闭防火墙测试**：
   - 系统设置 > 网络 > 防火墙 > 关闭
   - 在 Safari 中测试
   - 如果成功，说明是防火墙问题，需要配置例外

2. **检查后端服务日志**：
   ```bash
   tail -f /tmp/wanderlog_api.log
   ```
   查看是否有连接请求

3. **使用其他设备测试**：
   - 用另一台设备（如 iPad）测试
   - 确认是否是 iPhone 特定问题

## 💡 提示

后端服务配置正确（监听 `0.0.0.0`），所以问题通常是：
- 防火墙阻止了连接（90% 的情况）
- Mac 和 iPhone 不在同一网络
- 路由器阻止了设备间通信
